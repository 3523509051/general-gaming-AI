# 第 9 天论文实验记录（NitroGen 微调对照闭环）

> 日期：2026-08-25 ｜ 项目：general-gaming-AI（NitroGen 一键操作生成）
> 主题：零样本 vs 微调权重在离线逐帧口径下的对照实验，含测试集帧数与 IDLE 过滤的敏感性分析。

---

## 一、实验目标

验证「用游戏标注数据微调 NitroGen 一键操作生成模型」是否带来提升。论文声称微调后任务完成率相对提升 +10%~52%，本项目建立**离线逐帧对照闭环**进行验证，并探索两个关键选项：

1. **测试集帧数**（可自选，默认 200，已跑 200 / 500 / 5000）
2. **过滤 IDLE 帧**（is_idle = 双摇杆幅度 ≤0.1 且 17 键全 0，IDLE_THRESH=0.1）

---

## 二、对照体系（口径说明）

| 口径 | 说明 |
| --- | --- |
| **acc_B（acc_17keys_all）** | 主口径：逐帧全对——17 键全部一致才算该帧对（对齐课程参考水平约 50%） |
| **acc_A（acc_17keys_bits）** | 对照：逐键逐帧一致率（单帧 17 键全对视为 1，部分对按比例） |
| **acc_B 非IDLE（acc_17keys_all_nonidle）** | 仅非 IDLE 帧上的逐帧全对（过滤刷分帧） |
| **摇杆 corr / mse** | 左摇杆 x 轴相关/均方误差（shift 扫描最优） |
| **shift** | 预测-真值对齐偏移（0~17 扫描取 acc_B 最优） |

> 注意：**论文口径为在线任务完成率**（智能体实际跑游戏的通关/进度提升），与离线逐帧按键一致率不等价。离线提升小不否定在线提升。

---

## 三、实验结果（stories__the_path_of_destinies / v148388505，全流程 A100）

### 3.1 对照总表（微调权重：174000 帧，epochs=1，batch=16，lr=1e-4）

| 测试集 | 模型 | shift | acc_B 全帧 | acc_B 非IDLE | acc_A | corr_x | mse_x |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **200 帧**（129 非IDLE） | ng.pt 基线 | 0 | 0.5400 | 0.4574 | — | — | — |
| | ng_ft_174000 | 2 | **0.6000** | 0.4884 | — | — | — |
| | Δ | | **+0.060** | +0.031 | | | |
| **500 帧**（322 非IDLE） | ng.pt 基线 | — | 0.5420 | 0.4689 | — | — | — |
| | ng_ft_174000 | — | 0.5520 | **0.5093** | — | — | — |
| | Δ | | +0.010 | **+0.040** | | | |
| **5000 帧**（3275 非IDLE） | ng.pt 基线 | 0 | 0.5380 | 0.4827 | 0.9702 | 0.1638 | 0.4152 |
| | ng_ft_174000 | 1 | 0.5358 | 0.4754 | 0.9700 | 0.1476 | 0.4229 |
| | Δ | | **-0.0022** | **-0.0073** | -0.0002 | **-0.016** | +0.008 |

### 3.2 关键结论

1. **5000 帧（可靠统计）口径下，174k 帧微调在离线指标上无提升，略降**：
   - 按键一致率 Δ≈0（±0.01 内，统计噪声量级）
   - 摇杆轨迹略变差（corr_x 0.164→0.148，mse 略升）——微调可能牺牲摇杆平滑度
2. **500 帧的"过滤 IDLE Δ+0.04"是小样本波动假象**，5000 帧不成立——测试集帧数影响结论可靠性，小测试集（200/500）波动 ±0.04~0.06。
3. **IDLE 帧刷分现象确认**：200 帧中 35% 为 IDLE；5000 帧中 34.5%（3275/5000）。过滤 IDLE 后基线 acc 明显降低（0.538→0.483），说明 IDLE 帧大量"都按 0"抬高 acc。
4. 微调与论文差异归因：**在线任务完成率 vs 离线按键一致率**口径不同。在线 RL 微调优化游戏进度，不保证逐帧更像标注者。

## 四、实验基础设施（本日搭建/增强）

### 4.1 微调对照链路（阶段式）

```
阶段 0/2：零样本基线评估（evaluate.py --tag ng）
阶段 1/2：微调（finetune.py，按后端分发）
阶段 2/2：微调权重评估（evaluate.py --ckpt --tag ng_ft_{samples}）
→ compare 接口读两份 metrics 副本生成对照表
```

### 4.2 关键增强

| 能力 | 说明 |
| --- | --- |
| **跳过微调（eval_only）** | 权重已存在（本地文件 / 远程 /has_ckpt）→ 自动跳过阶段 1，仅重评估；换测试集帧数重测不重复微调（省 13h） |
| **基线放 A100** | 远程 worker 新增 `POST /eval_base`（evaluate.py 无 --ckpt），基线也高速评估；本地仅留 local 兜底 |
| **测试集帧数可调** | `--test-size`（10~5000）；基线副本按 n_frames 是否匹配自动复用/重跑，保证基线与微调同测试集 |
| **过滤 IDLE 双口径** | evaluate.py metrics 新增 `acc_17keys_all_nonidle` + `n_frames_nonidle`；对照表可切换全帧/非 IDLE 列 |
| **前端控件** | 面板新增「测试集帧数」「过滤 IDLE 帧」（可保存恢复）；深色实时日志终端 |
| **恢复接管** | 本地 Web 关闭后远程任务照跑，重开自动 recover 接管 + 回传 CSV（KB 级，权重留远程按需下载） |

### 4.3 环境

- 本地：8GB GPU（评估慢：5000 帧约 20 分钟）
- 远程：A100 80GB × 3（worker: 10.14.3.52:56272，微调+评估 5000 帧约 18 分钟）
- 产物：微调权重 `output/ng_ft_174000.pt`（留远程）；对照数据 metrics/predictions CSV 回传本地

## 五、工程问题与修复记录

| 问题 | 修复 |
| --- | --- |
| 链路固定"微调+评估"一体，二次运行重复微调 13h | 权重存在自动跳过微调（eval_only） |
| 基线评估本地慢（5000 帧 20 分钟） | worker 加 /eval_base，基线也放 A100 |
| 旧 metrics 无 nonidle 列导致 KeyError | compare 容错返回 null，前端提示重评估 |
| 重复 Web 进程并存（旧系统 Python + venv）导致本地重复跑基线 | 彻底清理，仅保留单一最新 Web |
| 前端 recover 缺 busy 分支显示"空闲" | busy 时启动轮询显示真实状态 |
| 本地状态不同步远程真实阶段（停在阶段 1） | 轮询时同步远程 stage 到本地 |

## B. 为什么"按键一致率高、摇杆相关低"（2026-08-22 数据驱动分析）

| 指标 | lies_of_p | hades |
| --- | --- | --- |
| 按键一致率 | 95.9% | 95.2% |
| 摇杆 8-方向命中率（活动帧） | **14.9%**（随机=12.5%） | **18.7%**（随机=12.5%） |
| IDLE 帧摇杆漂移幅度 | 0.482 | 0.593 |
| 预测 y 系统偏差 | -0.135 | -0.024 |

**结论（模型真实行为，非评估 bug）**：
1. **摇杆方向近乎随机**（14.9%/18.7% ≈ 随机 12.5%）——模型未精确学会摇杆方向。
2. **IDLE 帧也漂移**（0.48~0.59），无归零意识。
3. 按键离散 0/1 容易答对（大部分帧无按键），摇杆连续精确回归天生难——按键一致率高 = "容易的题答对多"。
4. 论文不承诺摇杆数值精度（主目标是任务完成率）。

**补充口径 1（幅度 r=√(x²+y²)）**：corr(r_pred, r_gt) = 0.121 / -0.046；移动分类一致率（阈值 0.1）= 69.2% / 48.0%；IDLE 帧"假移动"率 = 66.7% / 66.7% → 模型"知道摇杆一般推多大力，但不知道这一帧该推多少"。

**补充口径 2（动/不动二值一致率）**：69.2%（lies_of_p）/ 48.0%（hades），阈值 0.05~0.3 稳健 → 模型大体知道"这帧要不要推摇杆"，但 hades 被"过动"拖垮。**建议写入报告作为摇杆能力补充指标**。

## C. 评估口径敏感性（补充口径 3，2026-08-22）

按键一致率 3 种口径（同一测试集）：

| 口径 | lies_of_p | hades | 解读 |
| --- | --- | --- | --- |
| A. 逐键逐帧 | 95.9% | 95.2% | 宽松：IDLE 帧大量"都按 0"刷分 |
| B. **逐帧全对**（17 键全一致才算对） | 42.4% | 38.0% | **严格，非常接近参考水平 50%** |
| C. 仅真值有按键帧 | 92.2% | 92.1% | 去 IDLE 仍高 |

**重要推断**：参考水平"约 50%"很可能用的是口径 B——此前报 95% 是口径选宽了。
摇杆相关（全帧 vs 仅活动帧）：lies_of_p -0.06/-0.12 vs -0.08/-0.13；hades 0.05/0.04 vs 0.07/0.11——均未达标。
**报告口径建议**：按键同时报 A+B；摇杆报全帧+仅活动帧，并注明与参考水平的口径差异。

## D. 误触发率方向（扩展 B：IDLE/无效帧过滤，2026-08-23）

口径：FPR = 预测有按键且真值无按键帧 ÷ 真值无按键帧；过滤 = 分子分母均剔除 IDLE 帧（不改抽样/测试集）。

500 帧随机测试集实测：

| 游戏 | IDLE 占比 | 过滤前 FPR | 过滤后 FPR | 变化 |
| --- | --- | --- | --- | --- |
| hades | 41.6%（205） | 44.2%（142/321） | 43.1%（50/116） | ↓2.6% |
| lies_of_p | 17.4%（85） | 38.0%（128/337） | 39.3%（99/252） | ↑3.4% |

连续 200 帧（hades，--seq-mode）：36.0% → 58.3%（**↑61.9%**）。
三口径汇总（hades）：199 帧随机 ↓18% / 500 帧随机 ↓2.6% / 连续 200 帧 ↑62%。

**结论（负结果，如实报告）**：
1. **目标一（相对过滤前约 -20%）未达成**：IDLE 过滤对误触发率几乎无效甚至反升。
2. 根因：误触发**不是 IDLE 帧特有**，而是"真值无按键"帧的普遍问题（hades IDLE 44.9% vs 非 IDLE 43.1% 几乎一样高）。
3. A 方案（过滤口径）效果完全取决于测试集构成，不可靠；要降误触发只能靠 B 方案（抑制输出）。
4. 备用路径 B（识别 IDLE→预测按键强制置 0）预期：hades ↓65%、lies_of_p ↓9%（需真值 IDLE 标记/额外检测器，属上限分析），用户已确认暂不实现。

## E. 微调早期实验（扩展 A，2026-08-24，问题/结论记录）

1. **复现性**：同 ng.pt + 同 200 帧测试集，acc_B 0.420 vs 0.425、shift 0 vs 2 → flow-matching 采样随机 + 未固定 seed；**修复：evaluate.py 推理前 torch.manual_seed**。
2. **1k 档（hades）**：ng_ft_1k acc_B=0.430 vs ng 0.425（Δ+0.005）→ 落在推理采样噪声内（±0.005~0.01），**不能判定有效**。
3. **全帧 21600（lies_of_p）**：ng 0.449 vs ng_ft_21600 **0.480（Δ+0.0314，+3.1pp）**；best shift **12→0**（零样本要移 12 步才对齐标注、微调后天然对齐）→ **远超噪声，微调真实有效**，shift 变化是微调改变模型行为的铁证。
4. **与论文 +10~52% 差距**：论文口径是任务完成率（Gymnasium 实机），本表是离线按键一致率；计算方法自洽（acc_A^17≈acc_B：0.9586^17≈0.487↔0.449、0.9631^17≈0.528↔0.480）。
   - ⚠ 注意：开发日志另记 lies_of_p 全帧对照（基线 0.449 vs 0.4412，远程评估）与备忘 0.480 不同——seed 未固定时的采样波动，以固定 seed 重评估为准。
